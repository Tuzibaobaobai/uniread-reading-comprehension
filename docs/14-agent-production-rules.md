# UniRead 题目资源生产规约

**铁律（用户原文，2026-10-16）：我们一定要还原 RC 的布局和交互！**

接入UniRead时，必须保留RC原页布局、字体、响应式与交互，通过数据／存储／通信适配对接平台。RC原型API不是平台标准，不构成近似重写界面的许可；差异必须列为未完成并阻断原样还原验收。

交付可还原布局与交互的源码、字体／图片及构建依赖。以相同内容、视口、回答与位置对照来源页面、打包产物、平台容器，并记录交互证据；截图或保存成功不能替代原样还原验收。

版本：0.6，2026-10-17。对象：内容生产同事、Codex、Claude Code。本文规定生产输入和交付要求；平台解析／入库问题由接入方处理，不要求生产者填写数据库字段。RC是来源实现，不是UniRead标准。文中的“必须／不得”为交付要求，“待补／未验证”为合法但未完成的状态。本版补充第3.2节稳定题目ID与更新交接规则，不表示平台已实现跨版本答案继承。

## 0. 只收到两个文件时，如何使用

本文与`production-handoff.template.md`可以单独分发；不需要同时收到本项目的AGENTS.md或CLAUDE.md，也不依赖Agent自动加载任何入口文件。

1. 把两个文件放进同事实际生产项目的同一目录，例如`uniread-handoff/`，保留文件名。在Codex或Claude Code中打开该生产项目，明确要求Agent读取两个文件；仅复制文件不代表Agent已经读过。
2. 同时告诉Agent：本次生产／补齐哪套内容、现有内容与源码在哪、PDF／答案册／图片在哪、哪些材料暂缺，以及希望交付到哪个目录。两个文件是要求和模板，不包含完整题库、RC Schema、平台SDK或后端接口。
3. 第一次建议先做已有内容的差距检查，输出“已有／缺失／待确认”清单及拟修改文件；确认具体范围后再补齐。可直接复制第10节任务说明，并填上真实路径和范围。
4. 每次任务复制模板生成独立的`production-handoff.<本次任务标识>.md`，不要覆盖空白模板。交付源码、实际资产、私有答案文件及填好的交接文档；答案文件单独受控交付，不贴入公开交接文档。

本文中的仓库相对链接供在原RC仓库内查阅；独立分发后打不开不影响阅读本文。Agent应查找生产项目中实际存在的Schema、内容流程、设计规范和校验命令；找不到就报告缺失和影响，不要求同事取得本项目的AGENTS.md／CLAUDE.md，不凭本文重建RC结构或平台接口。阻塞项不妨碍先完成可确认部分的检查与交接说明。

## 1. Agent 开始前

1. 显式读取本文及随附的`production-handoff.template.md`。在原RC仓库内还应查阅已有[内容生产流程](04-content-pipeline.md)和[当前schema](../schema/index.ts)；在其他生产项目中，以实际找到的项目文件为依据，记录路径及缺失项。交付时填写模板。
2. 保留生产项目已有的数据结构和身份约定。使用RC时保留严格Item／Key／Playlist结构，已有Item ID及Question／blank ID不能随意重编；题号与ID分开。本文的补充信息写在独立交接文档，不直接加进strict JSON，不自行改Schema版本或平台协议。Schema缺失时先记录结构缺口，不猜测字段后批量改写数据。
3. 先检查现有文件与ID，再生产新内容；没有明确任务时不批量重写已有题目、页面或答案。不因格式／样式更新重建题目身份。
4. 无法取得PDF、答案册、授权信息或复核证据时，明确写“待补／未核对”，不得猜测页码、捏造版权、声称已人工复核或已发布。
5. 本文不授权推送、部署、正式审核或发布。平台权限、DB ID、OSS签名、学生身份、服务端时间和审核状态由平台提供。

## 2. 一次生产任务必须交付什么

| 交付物 | 必须包含 | 缺失时处理 |
| --- | --- | --- |
| 合集信息 | 稳定来源ID、名称／短名称、简介、语言、封面及其来源；已有series／publisher／gradeBand／version保留 | 缺封面或简介列待补，不靠展示页面临时拼接 |
| 试卷与大题清单 | 本次交付范围、稳定paperId／resourceId、大题标题与顺序、来源Playlist／Item／Section映射 | 边界未定就列映射待确认，不用整本书目录冒充一张试卷 |
| 题目公开内容 | 材料、Section说明、题干、选项／词库／空格、稳定ID、展示题号、分值及顺序 | 按原材料转录；识别不清须标记，不能凭答案补题 |
| 私有答案 | 与题目一一对应的Key、官方／生成来源、参考答案与解析、评分约束、独立版本／摘要及复核状态 | 可以generated／pending交接；不得为通过检查改成official／approved |
| 资产与构建 | 实际文件、相对路径、使用位置、来源；可构建源码、构建方法、依赖和入口 | 不仅交截图或易变网页；缺文件、外链、未交付视频列出 |
| 验证与未完成项 | 实际执行命令、结果、内容／答案分别复核的证据、能力缺口、待补项 | 没跑写未运行；RC通过不等于平台已接入或数据已保存 |

生产交接模板是给人和agent读取的附录，不是服务端接受的JSON协议；当前解析器不会自动读取该Markdown。已有RC字段由接入工具提取，新增说明先在附录保留。

## 3. 合集、试卷、大题的边界

- RC Playlist可以代表书籍／内容目录；平台考试Playlist代表明确的一套试卷。必须说明本次是“书籍目录”“整卷”还是“试点选材”，并区分原书总篇数、已生产数量和本次交付数量。
- 平台Resource可以是一道完形填空等大题，其内部有多个小题。不要以一个小题、一页PDF、一个React组件自动决定Resource边界。
- 一个Item可能有多个Section。必须逐道大题列出sourcePlaylistId、itemId、sectionIds、独立展示标题和排序。只写“每周精读”或“I／II／III”不够说明大题内容。
- 同一文章供多道大题使用时，在交接清单赋予稳定materialId并列出使用关系；现有Item内文章保持原结构，接入方负责平台映射。统计文章词数时按材料去重，不能因拆大题重复累计。
- 一个共享bank内的原子移词不能被拆成多个互不协调的资源。bank跨拟定大题时，先标明作用域并列为边界待确认；不得悄悄变成各题独立词库。
- 保留Item／Section／Question／blank／选项或词块ID。展示题号与题目身份分开处理，具体更新规则见第3.2节。普通微调不要求运营维护逐题映射；确有增删／换题／拆合时，由生产Agent在交接附录列出受影响ID与原因，不生成学生迁移指令，也不覆盖已发布版本。

### 3.1 可选的机器选材清单

只有在RC来源Item／Section及大题边界都能核对时，生产Agent才可额外交付一份独立的`production-selection.<本次任务标识>.json`，由接入方确认后使用。它不替代Markdown交接文档，不写进原来的strict Item／Key／Playlist。非RC项目或映射不完整时，在模板中列待确认即可，不猜Section ID，不为适应工具改写原题。

当前接入工具支持`rc-selection-2`，字段示例（仅示意结构，不代表原项目实际有这些ID）：

```json
{
  "format": "rc-selection-2",
  "sourceId": "rc-source",
  "paperId": "paper-one",
  "title": "本次试卷名称",
  "materials": [{"materialId":"article-one","playlistId":"book-a","itemId":"book-a-w01-mon"}],
  "resources": [
    {"resourceId":"reading-choice","title":"第一大题：阅读选择","playlistId":"book-a","itemId":"book-a-w01-mon","sectionIds":["s1"],"materialId":"article-one"},
    {"resourceId":"reading-detail","title":"第二大题：细节理解","playlistId":"book-a","itemId":"book-a-w01-mon","sectionIds":["s2"],"materialId":"article-one"}
  ]
}
```

- sourceId标识来源项目，paperId标识本次逻辑试卷，resourceId与materialId分别标识大题和材料，均为稳定的小写英文／数字／连字符标识（最多128字符），不是平台数据库ID或UUID；平台工具负责生成资源身份与摘要。改标题或样式不换这些ID。
- 每资源title是独立的大题展示名，非空、最多512字符、不能有控制字符；不覆盖文章原题名。resources顺序就是大题顺序，sectionIds必须来自实际来源并且在整卷内不重复选用同一个Item的同一Section。
- 当前一个material指一个Item.article；每资源只能引用同Item的一份article。相同Item的多道大题须引用同一个materialId，不把同文重复声明为两份材料。每份材料必须被使用；跨Item合并材料／一道大题多材料拼接暂列待适配。
- Section内的stimulus、说明、词库仍归对应大题；文章内未归属空格和跨大题bank问题仍会阻止构建，不能用materialId声明绕过。共享材料目前只共享身份和引用，HTML仍各自内联文章，不代表支持跨资源共享回答。
- 两个文件中的字段示例和能力状态以本文版本为准；最终是否能接入仍须平台解析／构建／Go校验和审核，不能因为生成了JSON就标记已发布。

### 3.2 稳定题目ID：同题保留，换题新建

目的：运营修改内容后，平台能够识别仍是同一道题的回答，并保留原卷记录。生产Agent维护ID和变更说明，运营无需填写兼容版本号、数据库字段或逐学生迁移表。以下规则是生产要求；自动升级、答案继承与历史快照仍由平台实现，不由生产Agent执行或宣称已生效。

**当前形式与作用域。** RC小题使用`q1`、`q2`等`q数字`字符串，展示题号在`number`字段；同一Item的全部Section之间小题ID必须唯一，不要求整本书的`q1`全局唯一。UniRead接入时原样保留小题ID，通过大题资源身份＋小题ID定位。生产交接的`sourceId`、`paperId`、`resourceId`以及同一来源的Item ID保持稳定；平台资源UUID由接入工具生成，生产者不要手填，也不要把releaseId、时间戳或内容摘要拼进每次重建的小题ID。

下文`q数字`和`number`示例采用RC现有格式。其他生产项目沿用自身Schema已有的合法ID格式，执行同样的稳定／不复用原则，不为模仿RC而批量改成`q数字`或擅自新增字段。

**开始更新前。** 先读取本次修改前的Item、私有Key、资产引用及可取得的上一份交付／Git记录，确认实际已用和退役ID。基线不存在时明确写“首次生产”或“旧版基线缺失”；没有旧版不能声称“已核对跨版本身份”或“旧答案可继承”。保留整份旧文件或可定位revision，不用当前文件反推旧题。

| 修改内容 | 小题ID如何处理 | 交接要求 |
| --- | --- | --- |
| CSS、布局、字体、题目调序、确认不改变题意的勘误 | 原题保留原ID；调序只改展示题号和顺序 | 无ID变化可写一句“全部沿用”；勘误列明修改点与判断依据 |
| 新增题 | 分配该来源作用域历史未用过的ID；RC按已知最大历史编号递增分配`q数字`，不按插入位置挤占旧ID | 只列新增ID与展示位置；历史范围无法确认时列待确认 |
| 删除题 | 从新版题目／Key中移除，旧版文件与退役记录保留；旧ID不得分配给另一道题 | 只列退役ID和原题来源，不操作学生记录 |
| 改变题意、换材料含义、选项含义或回答方式 | 受影响题目使用新ID；原题ID作为退役记录保留 | 列原ID、新ID及换题原因；拿不准是否同题时先标待确认，不猜兼容 |
| 仅修正私有标准答案／分值 | 题意、选项和回答结构不变时保留题目ID | 单列答案／评分规则变更，保持真实复核状态；不声称旧成绩已重算 |

关联ID也要保持语义：同一选项、空格、词块仍用原ID；不能为了重新显示A／B或空格序号而把另一个内容塞进旧ID。需要改变选项含义、空格归属／回答结构时按上表换题，并同步Key和引用。若页面把选项ID直接作为显示字母，不能通过交换A／B的内容伪装成单纯调序；显示能力不足列待适配。

共享文章或题图的实质含义变化，要检查所有依赖它的题目；共享bank的选项含义、可用次数或约束变化，要检查该bank的全部关联题目。所有受影响题目一起分配新ID，不能只换其中一道而让平台误继承其余回答。材料／图片更换不自动等于“只是样式变化”。

示例：某Item历史已有`q1`、`q2`。在两题之间插入新题时，目标身份与展示关系为：

```text
展示第1题：id=q1，number=1（原题）
展示第2题：id=q3，number=2（新增题）
展示第3题：id=q2，number=3（原题，ID不变）
```

**当前RC工具缺口，不能隐藏。** 截至本版，RC的`schema/index.ts`允许`q数字`，但`docs/04-content-pipeline.md`及`scripts/validate.ts`还要求ID按题号连续并满足`id=q{number}`。因此上述插题／保留ID调序示例目前不能通过原校验器。这是待接入方与生产项目维护方协调的工具约束，不是要求Agent重编号的理由。遇到该冲突，保留旧版基线、记录目标ID／题号及实际校验错误，交接状态写“ID与题号耦合，待适配”；不要为制造通过而重编号、关闭校验、擅改Schema或新增未定义的`stableId`字段。首次生产且没有旧身份时，仍可沿用当前连续`q1…qN`；已发布内容的插题／调序需要先解除此工具冲突。

变更清单由Agent按模板自动整理，仅列受影响项，不要求手抄所有未改题目。跨文件同步检查Item题目、Key.answers索引、questionId、blank引用、选项／bank引用、资源选材和位置引用；删除、换题或调序后不得残留指向其他题目的旧引用。此Markdown记录目前不会被BE自动解析成兼容结论。

## 4. 元数据不能混用

| 来源信息 | 生产要求 |
| --- | --- |
| gradeBand（如G7） | 说明学校年级；不等于UniRead L7 |
| difficulty（原书难度） | 保留原值与量表来源；不改名为UniRead等级或Lexile |
| wordCount | 保留原书标注／计算值并注明统计范围；重新计算或估计须注明方法，不冒充原书数据 |
| suggestedMinutes | 建议用时，注明原书／估算来源；不是考试限时、真实作答时长或资源duration |
| hasVideo | 只是来源声明；有书上讲解标记不等于交付了可用视频。说明本次是否包含视频及文件位置 |
| publisher／author／series | 照实保留，未知作者写未知；出版社名称不能代替版权和使用说明 |
| 源内容／答案review状态 | 原样保留并附证据；不代表UniRead审批通过，也不由生产agent批准平台发布 |

没有可靠测量／授权时，不生成UniRead等级、Lexile、版权授权结论或正式限时来“补齐字段”。可以在交接附录写待测／待确认，不要给RC strict对象添加这些字段。

## 5. 封面、缩略图和其他资产

- 合集封面必须提供实际文件及来源。每个大题明确选择“独立缩略图／复用合集封面／平台占位图”，不要求无图题强行裁图。现有RC thumbnail没有值时，在附录说明选用策略。
- 资产放在现有content/assets中，以assets/...相对路径引用；不得使用本机绝对路径、越界路径、符号链接、临时签名URL、凭据或未声明外链。
- 在清单中列明文件使用位置和来源；同图复用可以引用同一文件，不必复制。接入方负责计算文件SHA、上传和生成URL，生产者不要手写OSS对象键或签名。
- 页面必须能被接入工具打包。交代字体、图片、音视频、接口和模型等依赖；远程依赖未获支持时明确阻塞，不能仅凭本机能显示就标为可交付。
- 不把钥匙、答案册、正确选项或未开放解析混进公开资产／JS／HTML。检查最终产物和网络请求，目录名为keys或private不构成隔离保证。

## 6. PDF、内容与答案证据

- 保留source.pdf、pdfPages、bookPages与页面图对应关系。在原RC仓库内按[内容流程](04-content-pipeline.md)核对；独立使用时核对实际PDF、书页与页面图，记录换算依据，无法核对则标待核对。不默认所有书相同偏移。
- 交接附录给出可供同事定位的材料位置／标识，以及可获得时的版本／摘要；不要记录带Token的临时链接。源材料不在仓库时说明获取方式和当前可访问情况。
- 内容转录与答案正确性分别检查。内容reviewed时，答案仍可generated／pending；官方答案也要保留答案册出处，不把来源事实当平台审核决定。
- 无官方答案时标generated并提供推理／证据；无法确认则列待复核。不得删除难题、伪造选项或更改题干以适应当前评分器。
- 复核记录说明对象、版本、复核者或工具、方法、结论和仍未解决的问题。生产agent自检不得伪装成独立人工复核。

## 7. 每类题目必须说明的回答语义

| 题型 | 必须说明 | 需要的边界样例 |
| --- | --- | --- |
| 单选／判断 | 稳定选项ID、选择基数、未答／清空 | 换选、清空、非法选项、恢复 |
| 完形 | blank归属、各题选项、材料定位关系 | 点空格切题、选项恢复；提示不是学生回答 |
| 共享词／句库 | bank作用域、可用次数、每空归属、跨题移动影响范围 | 同批释放旧题＋填入新题；失败不只保存一半 |
| 文本填空 | 原始字符串、每空提示、词数限制、多空整题还是逐空评分 | 空串、部分草稿、Unicode、首字母、同义答案 |
| 连线 | 左右项ID、一对一或可重用、重配行为 | 部分配对、重复使用、释放、恢复；不用像素坐标存答案 |
| 连词成句 | 词块ID、原始文字、顺序和标点、部分草稿 | 重复文本不同ID、遗漏／撤回、多个正确顺序 |
| 开放问答 | 原始文本、私有rubric／要点／满分、评分依赖 | 未评、待评、失败与复核；不把自评分当正式成绩 |

只保存学生回答，菜单展开、鼠标悬停、待放置词条等是临时UI状态。最后questionId／可选partId与回答独立：未回答也能记录浏览位置；不能用最后一道已答题或阅读进度代替。

页面与交互仍遵循生产项目已有设计；点击／触控即可完成操作，不能只能拖拽，触控目标至少44px、输入字号至少16px，不使用原生select。在原RC仓库内遵守其设计Token。平台页面通过宿主／SDK提交回答变化，不持有主站Token、不直连模型、不把/api/rc/grade、/api/rc/judge或localStorage当成UniRead保存接口。返回合集表达为平台导航意图，不硬编码独立站路由。

## 8. 当前平台能力与生产选择

截至本文日期，BE实验分支的draft-2支持single-selection和slot-selection，已能适配单选／部分完形及共享词库的回答结构；自包含HTML构建、隔离宿主、FE与BE的小题保存／位置恢复、STAGED登记及只读审核准备已有本地隔离验证。另已支持显式选材2的大题标题／单Item文章材料映射，以及登记3中的结构校验和只读审核材料。正式本地BE已连接真实测试数据库并通过普通FE登录；真实RC包的OSS导入／正式发布／学生全链路、正式交卷评分仍未完成验收。跨发布版本继承答案与历史快照仍是设计，不能据本规约标为已支持。

- 当前优先用单选／共享词库做可接入样例，但具体资源仍需通过选材、材料分区与构建检查。
- textEntry、match、order、extendedText可以按RC schema生产，交接时必须列为待平台适配，不假称已支持。不可把它们伪装成单选以绕过校验。
- 生产者不自创SDK消息名或接口路径。获得实际平台SDK／样例后按其版本接入；原型可保留，但清楚标注实验适配器。
- 正式限时、重做、评分降级、反馈开放、审批角色等未定规则不由生产agent选择默认值。
