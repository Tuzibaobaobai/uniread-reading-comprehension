# UniRead 题目资源生产规约

**铁律（用户原文，2026-10-16）：我们一定要还原 RC 的布局和交互！**

接入UniRead时，必须保留RC原页布局、字体、响应式与交互，通过数据／存储／通信适配对接平台。RC原型API不是平台标准，不构成近似重写界面的许可；差异必须列为未完成并阻断原样还原验收。

交付可还原布局与交互的源码、字体／图片及构建依赖。以相同内容、视口、回答与位置对照来源页面、打包产物、平台容器，并记录交互证据；截图或保存成功不能替代原样还原验收。

版本：0.10，2026-10-22。对象：内容生产同事、Codex、Claude Code。本文规定生产输入和交付要求；平台解析／入库问题由接入方处理，不要求生产者填写数据库字段。RC是来源实现，不是UniRead标准。文中的“必须／不得”为交付要求，“待补／未验证”为合法但未完成的状态。本版同步RC当前稳定ID校验及既有媒体／截图／版本绑定流程；继续要求同类资源遵守既定规约，明确数据语义、源码依赖与验证责任；不把组件拆分固化为上游契约，也不要求保留旧测试答案、成绩或历史。

## 0. 只收到两个文件时，如何使用

对外分发的规范始终只有两份：`14-agent-production-rules.md`（要求）与`production-handoff.template.md`（填写结果）。可直接复制仓库`examples/agent-production/`中的这两个文件；仓库内的`docs/14-production-handoff.template.md`是同一模板的文档副本，对外使用前述文件名。两个文件可以单独分发；不需要同时收到本项目的AGENTS.md或CLAUDE.md，也不依赖Agent自动加载任何入口文件。内容包、媒体包、机器选材清单和截图属于生产产物，不是新增的必读规范文件。

1. 把两个文件放进同事实际生产项目的同一目录，例如`uniread-handoff/`，保留文件名。在Codex或Claude Code中打开该生产项目，明确要求Agent读取两个文件；仅复制文件不代表Agent已经读过。
2. 同时告诉Agent：本次生产／补齐哪套内容、现有内容与源码在哪、PDF／答案册／图片在哪、哪些材料暂缺，以及希望交付到哪个目录。两个文件是要求和模板，不包含完整题库、RC Schema、平台SDK或后端接口。
3. 第一次建议先做已有内容的差距检查，输出“已有／缺失／待确认”清单及拟修改文件；任务已明确授权补齐范围时可直接按范围执行，范围未定时先确认再补齐。可直接复制第10节任务说明，并填上真实路径和范围。
4. 每次任务复制模板生成独立的`production-handoff.<本次任务标识>.md`，不要覆盖空白模板。交付源码、实际资产、私有答案文件及填好的交接文档；答案文件单独受控交付，不贴入公开交接文档。

本文中的仓库相对链接供在原RC仓库内查阅；独立分发后打不开不影响阅读本文。Agent应查找生产项目中实际存在的Schema、内容流程、设计规范和校验命令；找不到就报告缺失和影响，不要求同事取得本项目的AGENTS.md／CLAUDE.md，不凭本文重建RC结构或平台接口。阻塞项不妨碍先完成可确认部分的检查与交接说明。

## 1. Agent 开始前

1. 显式读取本文及随附的`production-handoff.template.md`。在原RC仓库内还应查阅已有[内容生产流程](04-content-pipeline.md)和[当前schema](../schema/index.ts)；在其他生产项目中，以实际找到的项目文件为依据，记录路径及缺失项。交付时填写模板。
2. 沿用生产项目实际Schema和身份约定，已有Item／Question／blank／turn ID不能随意重编，题号与ID分开。交接说明放附录，不往strict JSON随意塞入平台字段。同类资源必须先复用既定Schema和语义，不能因重新生成而自创另一套。只有现有规约确实无法表达新的必要语义且属于本次已授权范围时，才可扩展来源Schema，并按第2.2节处理规约／版本、校验、样例和变更说明；不得只关闭校验、添加未定义字段或更改平台协议来绕过问题。Schema缺失或语义不明确时列缺口，不猜测后批量改写。
3. 先检查现有文件与ID，再生产新内容；没有明确任务时不批量重写已有题目、页面或答案。不因格式／样式更新重建题目身份。
4. 无法取得PDF、答案册、授权信息或复核证据时，明确写“待补／未核对”，不得猜测页码、捏造版权、声称已人工复核或已发布。
5. 本文不授权推送、部署、正式审核或发布。平台权限、DB ID、OSS签名、学生身份、服务端时间和审核状态由平台提供。

## 2. 一次生产任务必须交付什么

| 交付物 | 必须包含 | 缺失时处理 |
| --- | --- | --- |
| 合集信息 | 稳定来源ID、名称／短名称、简介、语言、封面及其来源；已有series／publisher／gradeBand／version保留 | 缺封面或简介列待补，不靠展示页面临时拼接 |
| 试卷与大题清单 | 本次交付范围、稳定paperId／resourceId、大题标题与顺序、来源Playlist／Item／Section映射 | 边界未定就列映射待确认，不用整本书目录冒充一张试卷 |
| 题目公开内容 | 材料、Section说明、题干、选项／词库／空格、稳定ID、展示题号、分值及顺序 | 按原材料转录；识别不清须标记，不能凭答案补题 |
| 私有答案 | 与题目一一对应的Key、官方／生成来源、参考答案与解析、评分约束、独立版本／摘要及复核状态 | 可以generated／pending交接；不得为通过检查改成official／approved |
| 资产与构建 | 实际文件、相对路径、使用位置、来源；可构建源码、构建方法、依赖和入口 | 不仅交截图或易变网页；缺文件、外链、未交付视频列出 |
| 验证与未完成项 | 实际执行命令、结果、内容／答案分别复核的证据、能力缺口、待补项 | 没跑写未运行；RC通过不等于平台已接入或数据已保存 |

生产交接模板是给人和agent读取的附录，不是服务端接受的JSON协议；当前解析器不会自动读取该Markdown。已有RC字段由接入工具提取，新增说明先在附录保留。

### 2.1 生产方与平台接入方的职责

| 生产方必须交付／说明 | 接入方负责实现与验证 |
| --- | --- |
| 真实内容、公开／私有边界、回答和评分语义、稳定ID与关联约束 | 数据投影、平台契约和存储扩展、服务端校验与判分 |
| 来源可运行源码、入口、依赖声明与锁文件、真实资产、外部能力依赖 | 在隔离快照中提取／改写组件、替换状态和依赖、接入宿主通信与受控能力 |
| 原页面的行为、响应式、已知问题及可复现场景 | 来源→产物→宿主的功能、数据保存与严格视觉验收 |
| 本次新题型／规则／Schema／代码结构变更及实际检查结果 | 判断旧适配规则是否适用；必要时更新规则、生成可审阅差异并记录来源／改写／规则哈希 |

生产方无需预先提供ReaderView、controller或指定目录拆分；可使用本项目合理的组件和状态组织。原型API／本地存储可作为独立站实现保留，但必须列清依赖和作用；接入方负责隔离／替换，不能将其直接当作平台保存或评分接口。生产方仍不得在公开产物中交付真实密钥或私有答案。

平台识别到陌生代码结构时，由接入方审阅并更新规则，不能要求上游仅为匹配旧组件名回退设计，也不能只更新哈希强行通过。规约约束数据和可观察行为，不承诺AI每次生成相同代码结构。


### 2.2 同类资源必须持续遵守既定规约

**强制要求：同类资源在首次生产、后续新增、补齐、重生成和更新时，始终使用该类资源已确立的规约。** 不得因不同生产批次、书籍、Agent或组件实现而另创等价但不一致的数据或行为约定。交付源码和变更说明，不能豁免规约符合性。

- **确认同类范围与依据。** 开始前识别资源类别、题型／回答族、模式及适用版本，读取本规约、已确认的该类约定、来源Schema／校验器和已验证参考样例。以明确确认的规约为准，不能把任意旧生成结果或校验器已有缺陷当成标准。KET／PET或不同题型可有明确的专属规则，不因页面外观相似而强行混为一类。
- **保持外部一致。** 同类同版本的数据字段名、类型、层级与ID作用域、回答形状、未答／清空含义、共享与选题约束、计分材料结构、资产引用方式、公开／私有边界及已约定交互必须一致。不能一个批次用字符串回答、另一个用数组，或悄悄改变空串、bank复用和未选题计分的含义。题目内容、数量、分值或时长等可以在该类规约允许的参数范围内变化，不要求不同试卷内容完全相同。
- **复用既有能力。** 同类资源应复用已有的数据校验、渲染／交互能力、设计tokens和样式约定，不为每卷另建一套平行协议或行为。内部组件拆分、文件路径、状态管理可以合理演进，但必须保持既定外部数据与可观察行为，不能把内部变化转化为每批不同的交付契约。
- **必要扩展必须显式处理。** 先证明现有约定无法表达什么，列出新增语义、适用范围、旧版差异和影响。改变既定约定须有明确授权；本次任务已明确授权该扩展时无需重复确认。同步更新该类规约／来源Schema、版本说明、校验和有效／无效样例，并验证已有同类资源与旧题型影响。不兼容变化须明确版本区分及重新生成／转换策略，不得伪装成同版本兼容；RC发生不兼容Schema变更时，按项目要求更新`schema/index.ts`中的`SCHEMA_VERSION`及`docs/03-data-model.md`；其他来源Schema没有版本字段时记录在交接中，不往strict JSON硬加字段。无需迁移旧测试成绩或历史。
- **偏离不能靠接入兜底。** 已有规约能表达而本次实现不符合时，由生产方修正；不能仅写“待平台适配”就宣称生产交付通过。新语义尚未确认时列待确认，不自行选择默认值。缺少可靠基线时如实记录，先完成可确认部分，不能宣称已符合该类规约。
- **交付必须有一致性证据。** 在同一套适用校验与行为案例下检查本次新资源及有代表性的已有同类资源，列出基线版本／样例、实际检查范围、差异和结果。发现差异区分内容参数变化、内部重构与规约变化；新资源能单独运行不能替代同类一致性验证，未通过不得标为符合规约。

### 2.3 RC既有交付格式与版本绑定

以下按RC当前`HANDOFF.md`及交付脚本约定整理（本版核对基线：`e46285e`）。在RC生产时直接沿用这些产物与清单，不另建一套同义格式；其他来源项目沿用其已有等价产物并说明映射。后续来源流程变化时核对实际版本并同步规约，不将旧tag当作每批固定版本。

| RC产物 | 内容与边界 |
| --- | --- |
| `rc-content-public.zip` | catalog、playlist、item及图片；不含Key、音频或视频 |
| `rc-media-<合集>.zip`及包内`MEDIA.json` | 保留`assets/<合集>/…`相对路径；清单沿用`playlist`、`format`、`files`，文件项含`path`、`bytes`、`sha256`、`seconds`、`usedBy`，核对真实文件、时长和引用位置。听力采用AAC 48 kbps单声道，口语考官TTS采用mp3 64 kbps；由UniRead托管到自己的存储／CDN |
| `MANIFEST.sha256` | 沿用RC对公开内容文件的SHA-256清单；媒体文件摘要在`MEDIA.json`，不得将该清单描述为已覆盖未列出的附件 |
| `production-handoff.md` | 本批次已填写的交接说明；可由独立任务交接文档整理，不覆盖空白模板 |
| `production-selection.<paperId>.json` | 适用时每份逻辑试卷一份`rc-selection-2`；沿用第3.1节。RC现有release交付包含此项，映射未确认时列缺口，不伪造清单 |
| `rc-reference-screens-<视口>.zip` | 作答前来源截图，按`desktop`、`ipad-landscape`、`ipad-portrait`分包；不得混入含答案的复盘截图 |

内容包、源码、私有Key与截图须对应同一来源tag及其固定commit，交接中记录两者；已有交付如`v0.4-handoff`只是一个版本实例。私有Key从同tag的`content/playlists/<合集>/keys/<itemId>.json`受控取得，不放进公开release附件、前端包或CDN。含答案复盘截图在同tag本地生成，位于`.work/reference/private/<视口>/`，仅用于受控验收；作答前截图位于`.work/reference/public/<视口>/`。仓库本身若公开，须如实记录私有材料的实际可见性，不能仅因文件位于`keys/`就声称已经隔离。

使用`REFERENCE=1 npx playwright test e2e/reference.spec.ts`生成来源截图并记录实际覆盖与失败项；打包可沿用`scripts/make-handoff-release.mjs`，但须核对本批次范围、交接文档及附件是否正确，不能把传入tag名称当作代码已切换至该tag的证据。媒体未取得、截图未运行或版本不一致时写明缺口，不宣称交付完整；本规约不授权推送或发布。

## 3. 合集、试卷、大题的边界

- RC Playlist可以代表书籍／内容目录；平台考试Playlist代表明确的一套试卷。必须说明本次是“书籍目录”“整卷”还是“试点选材”，并区分原书总篇数、已生产数量和本次交付数量。
- 平台Resource可以是一道完形填空等大题，其内部有多个小题。不要以一个小题、一页PDF、一个React组件自动决定Resource边界。
- 一个Item可能有多个Section。必须逐道大题列出sourcePlaylistId、itemId、sectionIds、独立展示标题和排序。只写“每周精读”或“I／II／III”不够说明大题内容。
- 同一文章供多道大题使用时，在交接清单赋予稳定materialId并列出使用关系；现有Item内文章保持原结构，接入方负责平台映射。统计文章词数时按材料去重，不能因拆大题重复累计。
- 一个共享bank内的原子移词不能被拆成多个互不协调的资源。bank跨拟定大题时，先标明作用域并列为边界待确认；不得悄悄变成各题独立词库。
- 保留Item／Section／Question／blank／选项或词块ID。展示题号与题目身份分开处理，具体更新规则见第3.2节。普通微调不要求运营维护逐题映射；确有增删／换题／拆合时，由生产Agent在交接附录列出受影响ID与原因，不生成学生迁移指令，也不覆盖已发布版本。

### 3.1 可选的机器选材清单

只有在RC来源Item／Section及大题边界都能核对时，生产Agent才可额外交付一份独立的`production-selection.<本次任务标识>.json`，由接入方确认后使用。它不替代Markdown交接文档，不写进原来的strict Item／Key／Playlist。非RC项目或映射不完整时，在模板中列待确认即可，不猜Section ID，不为适应工具改写原题。

当前接入工具支持`rc-selection-2`，字段示例（仅示意结构，不代表原项目实际有这些ID）：

```json
{
  "format": "rc-selection-2",
  "sourceId": "uniread-rc",
  "paperId": "paper-one",
  "title": "本次试卷名称",
  "materials": [{"materialId":"article-one","playlistId":"book-a","itemId":"book-a-w01-mon"}],
  "resources": [
    {"resourceId":"reading-choice","title":"第一大题：阅读选择","playlistId":"book-a","itemId":"book-a-w01-mon","sectionIds":["s1"],"materialId":"article-one"},
    {"resourceId":"reading-detail","title":"第二大题：细节理解","playlistId":"book-a","itemId":"book-a-w01-mon","sectionIds":["s2"],"materialId":"article-one"}
  ]
}
```

- RC现有来源标识为`uniread-rc`，沿用已有机器清单时保持不变；其他项目使用自身稳定来源标识。sourceId标识来源项目，paperId标识本次逻辑试卷，resourceId与materialId分别标识大题和材料，均为稳定的小写英文／数字／连字符标识（最多128字符），不是平台数据库ID或UUID；平台工具负责生成资源身份与摘要。改标题或样式不换这些ID。
- 每资源title是独立的大题展示名，非空、最多512字符、不能有控制字符；不覆盖文章原题名。resources顺序就是大题顺序，sectionIds必须来自实际来源并且在整卷内不重复选用同一个Item的同一Section。
- 当前一个material指一个Item.article；每资源只能引用同Item的一份article。相同Item的多道大题须引用同一个materialId，不把同文重复声明为两份材料。每份材料必须被使用；跨Item合并材料／一道大题多材料拼接暂列待适配。
- Section内的stimulus、说明、词库仍归对应大题；文章内未归属空格和跨大题bank问题仍会阻止构建，不能用materialId声明绕过。共享材料目前只共享身份和引用，HTML仍各自内联文章，不代表支持跨资源共享回答。
- 两个文件中的字段示例和能力状态以本文版本为准；最终是否能接入仍须平台解析／构建／Go校验和审核，不能因为生成了JSON就标记已发布。

### 3.2 稳定题目ID：同题保留，换题新建

目的：更新内容时能辨识同题、换题及其引用，避免把不同题目误当成同一道题。当前测试环境不要求保留旧答案、成绩或历史；稳定内容ID仍用于准确映射和审计。生产Agent维护ID和变更说明，运营无需填写兼容版本号、数据库字段或逐学生迁移表。以下规则是生产要求；自动升级、答案继承与历史快照仍由平台实现，不由生产Agent执行或宣称已生效。

**当前形式与作用域。** RC小题使用`q1`、`q2`等`q数字`字符串，展示题号在`number`字段；同一Item的全部Section之间小题ID必须唯一，不要求整本书的`q1`全局唯一。UniRead接入时原样保留小题ID，通过大题资源身份＋小题ID定位。生产交接的`sourceId`、`paperId`、`resourceId`以及同一来源的Item ID保持稳定；平台资源UUID由接入工具生成，生产者不要手填，也不要把releaseId、时间戳或内容摘要拼进每次重建的小题ID。

下文`q数字`和`number`示例采用RC现有格式。其他生产项目沿用自身Schema已有的合法ID格式，执行同样的稳定／不复用原则，不为模仿RC而批量改成`q数字`或擅自新增字段。

**开始更新前。** 先读取本次修改前的Item、私有Key、资产引用及可取得的上一份交付／Git记录，确认实际已用和退役ID。基线不存在时明确写“首次生产”或“旧版基线缺失”；没有旧版不能声称“已核对跨版本身份”或“旧答案可继承”。保留整份旧文件或可定位revision，不用当前文件反推旧题。

| 修改内容 | 小题ID如何处理 | 交接要求 |
| --- | --- | --- |
| CSS、布局、字体、题目调序、确认不改变题意的勘误 | 原题保留原ID；调序只改展示题号和顺序 | 无ID变化可写一句“全部沿用”；勘误列明修改点与判断依据 |
| 新增题 | 分配该来源作用域历史未用过的ID；RC按已知最大历史编号递增分配`q数字`，不按插入位置挤占旧ID | 只列新增ID与展示位置；历史范围无法确认时列待确认 |
| 删除题 | 从新版题目／Key中移除，旧版文件与退役记录保留；旧ID不得分配给另一道题 | 只列退役ID和原题来源，不操作学生记录 |
| 改变题意、换材料含义、选项含义或回答方式 | 受影响题目使用新ID；原题ID作为退役记录保留 | 列原ID、新ID及换题原因；拿不准是否同题时先标待确认，不猜兼容 |
| 仅修正私有标准答案／分值 | 题意、选项和回答结构不变时保留题目ID | 单列答案／评分规则变更，保持真实复核状态；不声称旧成绩已重算 |

关联ID也要保持语义：同一选项、空格、词块仍用原ID；不能为了重新显示A／B或空格序号而把另一个内容塞进旧ID。需要改变选项含义、空格归属／回答结构时按上表换题，并同步Key和引用。若页面把选项ID直接作为显示字母，不能通过交换A／B的内容伪装成单纯调序；显示能力不足列待适配。

共享文章或题图的实质含义变化，要检查所有依赖它的题目；共享bank的选项含义、可用次数或约束变化，要检查该bank的全部关联题目。所有受影响题目一起分配新ID，不能只换其中一道而让平台误继承其余回答。材料／图片更换不自动等于“只是样式变化”。

示例：某Item历史已有`q1`、`q2`。在两题之间插入新题时，目标身份与展示关系为：

```text
展示第1题：id=q1，number=1（原题）
展示第2题：id=q3，number=2（新增题）
展示第3题：id=q2，number=3（原题，ID不变）
```

**当前RC校验已支持ID与题号分离。** `schema/index.ts`规定小题ID为`q数字`；`scripts/validate.ts`检查同一Item内ID唯一及展示题号从1连续，不要求`id=q{number}`，上述插题示例符合这两项约束，完整内容仍须通过全部校验。更新已有内容时，用`npx tsx scripts/id-changes.ts --base <基线tag或commit>`生成变更表并检查退役ID复用，结合实际题意复核；脚本不能代替同题／换题判断。如果实际生产项目是仍绑定ID与题号的旧版本，记录来源revision及真实错误后列待适配，不将旧版本限制描述为当前RC要求，也不为通过校验重编号、关闭校验或新增未定义的`stableId`字段。

变更清单由Agent按模板自动整理，仅列受影响项，不要求手抄所有未改题目。跨文件同步检查Item题目、Key.answers索引、questionId、blank引用、选项／bank引用、资源选材和位置引用；删除、换题或调序后不得残留指向其他题目的旧引用。此Markdown记录目前不会被BE自动解析成兼容结论。

## 4. 元数据不能混用

| 来源信息 | 生产要求 |
| --- | --- |
| gradeBand（如G7） | 说明学校年级；不等于UniRead L7 |
| difficulty（原书难度） | 保留原值与量表来源；不改名为UniRead等级或Lexile |
| wordCount | 保留原书标注／计算值并注明统计范围；重新计算或估计须注明方法，不冒充原书数据 |
| suggestedMinutes | 建议用时，注明原书／估算来源；不是考试限时、真实作答时长或资源duration |
| hasVideo | 只是来源声明；有书上讲解标记不等于交付了可用视频。说明本次是否包含视频及文件位置 |
| publisher／author／series | 照实保留，未知作者写未知；出版社名称不能代替版权和使用说明 |
| 源内容／答案review状态 | 原样保留并附证据；不代表UniRead审批通过，也不由生产agent批准平台发布 |

没有可靠测量／授权时，不生成UniRead等级、Lexile、版权授权结论或正式限时来“补齐字段”。可以在交接附录写待测／待确认，不要给RC strict对象添加这些字段。

## 5. 封面、缩略图和其他资产

- 合集封面必须提供实际文件及来源。每个大题明确选择“独立缩略图／复用合集封面／平台占位图”，不要求无图题强行裁图。现有RC thumbnail没有值时，在附录说明选用策略。
- 资产放在现有content/assets中，以assets/...相对路径引用；不得使用本机绝对路径、越界路径、符号链接、临时签名URL、凭据或未声明外链。
- 在清单中列明文件使用位置和来源；同图复用可以引用同一文件，不必复制。生产方可从实际文件自动生成字节数与完整SHA-256，接入方重算核验并负责上传和生成URL；缺少摘要写待计算，不编造哈希，生产者不要手写OSS对象键或签名。
- 页面必须能被接入工具打包。交代字体、图片、音视频、接口和模型等依赖；远程依赖未获支持时明确阻塞，不能仅凭本机能显示就标为可交付。
- 不把钥匙、答案册、正确选项或未开放解析混进公开资产／JS／HTML。检查最终产物和网络请求，目录名为keys或private不构成隔离保证。

## 6. PDF、内容与答案证据

- 保留source.pdf、pdfPages、bookPages与页面图对应关系。在原RC仓库内按[内容流程](04-content-pipeline.md)核对；独立使用时核对实际PDF、书页与页面图，记录换算依据，无法核对则标待核对。不默认所有书相同偏移。
- 交接附录给出可供同事定位的材料位置／标识，以及可获得时的版本／摘要；不要记录带Token的临时链接。源材料不在仓库时说明获取方式和当前可访问情况。
- 内容转录与答案正确性分别检查。内容reviewed时，答案仍可generated／pending；官方答案也要保留答案册出处，不把来源事实当平台审核决定。
- 无官方答案时标generated并提供推理／证据；无法确认则列待复核。不得删除难题、伪造选项或更改题干以适应当前评分器。
- 复核记录说明对象、版本、复核者或工具、方法、结论和仍未解决的问题。生产agent自检不得伪装成独立人工复核。

## 7. 每类题目必须说明的回答语义

| 题型 | 必须说明 | 需要的边界样例 |
| --- | --- | --- |
| 单选／判断 | 稳定选项ID、选择基数、未答／清空 | 换选、清空、非法选项、恢复 |
| 完形 | blank归属、各题选项、材料定位关系 | 点空格切题、选项恢复；提示不是学生回答 |
| 共享词／句库 | bank作用域、可用次数、每空归属、跨题移动影响范围 | 同批释放旧题＋填入新题；失败不只保存一半 |
| 文本填空 | 原始字符串、每空提示、词数限制、多空整题还是逐空评分 | 空串、部分草稿、Unicode、首字母、同义答案 |
| 连线 | 左右项ID、一对一或可重用、重配行为 | 部分配对、重复使用、释放、恢复；不用像素坐标存答案 |
| 连词成句 | 词块ID、原始文字、顺序和标点、部分草稿 | 重复文本不同ID、遗漏／撤回、多个正确顺序 |
| 开放问答 | 原始文本、私有rubric／要点／满分、评分依赖 | 未评、待评、失败与复核；不把自评分当正式成绩 |

只保存学生回答，菜单展开、鼠标悬停、待放置词条等是临时UI状态。最后questionId／可选partId与回答独立：未回答也能记录浏览位置；不能用最后一道已答题或阅读进度代替。

页面与交互仍遵循生产项目已有设计；点击／触控即可完成操作，不能只能拖拽，触控目标至少44px、输入字号至少16px，不使用原生select。在原RC仓库内遵守其设计Token。平台页面通过宿主／SDK提交回答变化，不持有主站Token、不直连模型、不把/api/rc/grade、/api/rc/judge或localStorage当成UniRead保存接口。返回合集表达为平台导航意图，不硬编码独立站路由。

## 9. 交付前检查

在原RC项目中，有内容变更时按已有流程运行（替换真实itemId）：

```bash

```

先确认实际项目存在上述命令；其他生产项目使用其已有校验方式，不盲目套用npm命令，也不为满足本文而凭空新建工具链。源码／交互变更时再运行项目适用的build、test、e2e，并记录实际结果。只有文档修改时不需要重建内容索引。不要只附“全部通过”而不给命令／范围；warning逐项解释，内容和答案状态分别记录。

自动生成inventory或交接表后仍须逐项核对实际Schema和行为，尤其完整分卷／Part归属、共享bank作用域与复用次数、选题后的有效满分和能力状态；旧脚本的硬编码推断不构成来源事实。

- 同时交付 Section/Question/turn 稳定 ID 和顺序、PET choose-one 组、共享选项 bank 的唯一／复用／例题占用规则。录音转写按 turn ID，不能仅给 flatten 下标。空文本选题也有意义；平台回答与持久化由接入方适配。
- 音频提供真实文件、引用路径、MIME、字节数、SHA 和使用位置。缺失即写待补，不能用生成音频代替书籍录音后宣称真实听力通过。转写原文在私有 Key 内，不能内联到公开 Item。
- 四类 Cambridge 私有 rubric 和来源复核状态保持原样。估算量表与官方成绩分开；口语仅评转写可观察维度，不评发音。真实模型校准、实体 Safari/iPad 麦克风权限和自动播放分别留证。
- 当前平台使用统一 exam-1、登记格式 exam-registration-4。生产者交付 RC 原结构与资产，不往 strict JSON 添加平台修订、数据库 ID、Token 或对象键。公开页面保留来源布局与交互；ReaderView/ReaderFrame及受控能力可由平台在隔离副本提取／改写，不要求上游提供同名组件。


## 12. 新题型或新一轮AI生产的最少数据说明

下面描述的是需要交付的语义，不是要求所有项目改成同一种JSON或固定字段名。同类既定Schema能表达的必须直接沿用；表达不了的，按第2.2节在授权范围内扩展该类规约／来源Schema并同步版本说明、校验与样例，在交接中列清对应位置；尚未确认的先写待确认，不凭空制定平台接口。

| 对象 | 必须明确的数据／语义 |
| --- | --- |
| 内容层级与定位 | 试卷／分卷、Part、Question、blank／turn的归属、稳定ID、展示顺序及共享材料引用；持久定位不使用易变页码或数组下标 |
| 回答 | 原始回答形状、未答／空串／清空／部分草稿的区别，选择数量、词数限制；不靠渲染页面推断含义，不把临时展开／拖拽位置当回答 |
| 共享与选题 | bank的唯一／可复用次数、例题预占、跨题移动应释放哪些回答；选题组允许选几题、未输入时选择是否有效、换选清空哪些回答、未选题是否计分 |
| 口语与轮次 | 每轮稳定turn ID、顺序、提示／音频引用及回答归属；轮次切换、取消、重录和迟到转写的期望行为；音频、转写文本与评分结果分开说明 |
| 私有评分材料 | 对应Question／blank／turn，标准答案或参考文本、可接受变体、匹配／文本归一化规则、rubric及逐维满分、计分条件和答案来源／复核状态；公开交接只引用私有文件位置 |
| 练习与考试 | 来源实际模式、考试时长及依据（区别建议用时）、分Part播放／暂停／定位／重播规则、超时和重新开始行为；区分原书要求、来源实现、建议和已确认平台规则，未定项不取默认值 |
| 媒体与依赖 | 引用路径→实际文件→使用位置，格式／MIME、大小／可得摘要；原书录音、口语TTS和合成测试媒体分别标注；外链、模型／ASR及浏览器权限依赖明示 |
| 新增／变化项 | 相对哪版新增了什么题型、语义、Schema字段、页面流程或代码结构；旧题型受影响范围与回归结果，不能只写“兼容” |

### 12.1 媒体必须可交付，不以引用数量代替文件

RC沿用第2.3节的媒体包和`MEDIA.json`，直接引用现有清单，不要求另填重复inventory；补充其中未覆盖的来源类型、MIME、缺失项和时长核对结果。

音频因Git忽略而单独交付时，写明媒体包文件名、版本／可定位标识、解包后的相对根目录、引用数量、实际文件数量及缺失清单。可以用一个文件复用多个引用，但必须能逐引用定位到文件。原书听力、TTS和test-only合成音频分开统计；TTS标明文本来源、生成方式和使用条件，不标成原书官方录音。暂未收到媒体包只能记“本地未取得”，不能推断生产端从未产出。不得为了验收自行付费生成或用测试媒体冒充正式资产。

### 12.2 可复现源码与交付状态

交付来源revision或可定位快照；有未提交改动时附实际差异／文件摘要，不能只用HEAD代表交付代码。给出入口、运行时／包管理器版本、依赖声明与锁文件、构建／启动／检查命令、CSS／字体／图标／响应式依赖。列清路由、原型存储、HTTP、录音、ASR／模型和权限的调用位置与用途；无需预先实现平台SDK，也不交付真实凭据。

交接逐项使用“来源已验证／平台已验证／未运行／待补／待确认”，并附版本与证据；同时标注真实或模拟依赖。来源build通过、API成功、截图、媒体SHA都不能单独证明平台持久化、评分正确或原样还原。来源布局／交互的已知问题保留说明；接入改写及其验证由接入方记录，不让生产方冒填。
